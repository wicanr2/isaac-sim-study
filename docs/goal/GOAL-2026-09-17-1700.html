GOAL 7:IMU 優先——加速度計補平移打滑、yaw 融合進 odom

產生時間:2026-09-17 17:00。接續 GOAL 6(部分完成:#8–#10 已關,#7 realtime 連續注入閒時 C9 3/5、開放;總結在 issue #1 最後一則)。

使用者 2026-09-17 定的優先序:陀螺儀／IMU 列為首要。這一輪範圍涵蓋三件事:陀螺儀維持現況、加上加速度計、yaw 融合進 odom。

GOAL 6 的 IMU 只做到偵測:陀螺儀 yaw rate 對輪差 yaw rate,殘差超過門檻就亮 SLIP。留下三個缺口,形狀相同——感測器已經在匯流排上,系統卻只拿它做一件事:

  1. 平移打滑是盲區。 車正面頂住、兩輪等速時,陀螺儀與輪差都是 0。C13 對這種情況只報延遲,不判(+750 / +1280 ms,這段時間 odom 多走 280–441 mm)。
  2. odom 的航向只看輪差。 轉角打滑時 odom 的 θ 一路錯下去,要等 AMCL 或人來救。陀螺儀的讀值就在韌體手上,卻沒進里程計。
  3. 感測器是理想的。 橋接寫進去的是真值位姿差分,沒有零偏、沒有雜訊。45 mrad/s 門檻與「誤報 0」都是在理想感測器上量的,真板成不成立不知道。

這一輪依序處理:先補誤差模型,再做加速度計,最後做融合。每一條照舊先紅再綠、有數字、有負對照。

三條線(A 是 B、C 的前提;D 是 #7 的延續、優先序最低)

A. 感測器誤差模型(B、C 共用)

現況:bridge-rs/src/main.rs 用受控體真值位姿差分算 yaw rate,再乘最近 200 ms 的時鐘比(受控體時間 ÷ Renode 時間,38 篇 §1.3),原樣寫進 LSM330_Gyroscope_Fixed.AngularRateZ。加速度計的二次差分照同一個時間基準(乘時鐘比)。

  1. 參數從 datasheet 抄,不猜。 讀 LSM330 datasheet(DocID023426,列出版次與表號),把陀螺儀與加速度計各自的四項抄成表,寫進 36 篇 §3:零偏(zero-rate level / zero-g level)、雜訊密度、靈敏度誤差、溫漂。datasheet 沒寫的項目就寫「沒寫」,不從別的型號借。
  2. 橋接加誤差注入:--imu-noise none|datasheet。零偏每次跑固定、白雜訊用固定 seed;三個受控體(Rust Fake、fake_plant.py、Isaac)共用同一份公式,不經受控體協定(同 GOAL 6 陀螺儀的做法)。 - none 保留:理想感測器的數字要能重現; - lockstep 下同 seed 兩次逐 byte 相同。
  3. 重跑 C13 表(38 篇 §1.3)的正常四情境與 blind-scan,換成 datasheet: - 誤報仍要 0。不是 0 就先報告,門檻從帶雜訊的離線表重推,寫進 38 篇再改。不准悄悄調門檻。 - 轉角打滑的延遲與理想感測器並列。

B. 加速度計 → 平移打滑(#8 的缺口)

  1. 先盤點 Renode 模型,從原始碼列,不猜。 1.16.1 有 Sensors/LSM330_Accelerometer.cs(上游 master 也有)。 - 列出:暫存器表、FSCALE 對應的靈敏度換算、WHO_AM_I 有沒有實作、有沒有輸出飽和;逐項對 datasheet。 - 陀螺儀那份模型有兩個錯(靈敏度 130 對 114.3 digit/dps、WHO_AM_I 讀 0),同一作者的加速度計要假設可能有同類問題,逐項對過。 - 7-bit 位址照 datasheet 與板子接法(SA0)定,寫明依據。 - 有錯就修在模型:fork 分支基於 master、英文 commit、NUnit、1.16.1 執行期載入。上游 PR 稿給使用者看過才送。
  2. 先離線選訊號,不寫程式。 GOAL 6 的離線表(38 篇 §1.3)已經量到: - (b)「真值前進加速度 − 輪速微分」只抓得到撞上那一下,打滑期間超過門檻的比例 0.1%; - 持續的平移打滑裡車體加速度是 0、輪速也不變,兩邊都沒有訊號。

所以候選要換成能看出持續狀態的,至少比這三個: - (b1) 撞擊尖峰 + 之後輪速仍非零(事件式); - (b2) 加速度積分出的車體速度(漏積分、或只在「命令改變後一段窗」內積分)對輪速; - (b3) 加減速段的「命令加速度 vs 量到的車體加速度」。

每個候選在帶 A 的誤差模型的前提下報:平移打滑開始後幾 ms 可判定(假受控體兩次 head-on、Isaac blind-scan)、正常四情境誤報幾次。沒有這張表不選方案。 表顯示加速度計在 datasheet 零偏下分不出持續平移打滑,就照實寫、不硬做,把 (c) 雷射對地圖(需要雷射沒被遮的場景,例如低於掃描面的障礙物)列成替代方案回報。 3. 韌體:同一條 I2C3,每個控制步讀加速度計(每筆交易一個暫存器,同陀螺儀)。旗標沿用 SLIP 還是另開一位、亮了之後做什麼,先寫進 38 篇 §1.3 再做。韌體照舊只回報、不切。 4. 橋接:受控體真值位姿的二次差分轉到車體座標,當加速度計的機械部分。三個受控體同一份公式。Isaac 的接觸會讓二次差分出現尖峰——量出來,寫進表,不濾掉。 5. C13 升級:平移打滑從「只報延遲」改成有期限的判準,期限從離線表定(同 GOAL 6 轉角打滑取 3 倍的做法)。負對照 slip-off 要同時關掉兩種偵測、仍紅;另加一個只關加速度計的負對照,head-on 場景要紅。

C. yaw 融合進 odom

  1. 先設計、寫進 36 篇再做: - 融合方式,例如互補濾波:陀螺儀積分為主、輪差修低頻; - 零偏估計在什麼條件下更新,例如命令為 0 且兩輪 tick 都不動滿 N ms; - 數值格式:韌體是 -mfloat-abi=soft 的 float,照現有 control.c 的里程計寫法; - /odom 發出的航向換成融合值之後,打滑偵測的殘差仍用原始陀螺儀對輪差,不能拿融合值去比自己。
  2. 判準先寫進 38 篇再跑: - C3 的定義與容差不動。 融合後 C3 在正常四情境要照舊綠,融合前後的 dθ 並列。 - 新判準 C15(轉角打滑下的航向):blind-scan CONTACT=slip(假受控體)與 Isaac blind-scan,打滑期間 odom θ 對真值的最大誤差 ≤ 上限。上限從「只用輪差」那一次量到的誤差與陀螺儀誤差模型推,寫明推法。 - 負對照:--negative fusion-off(回到只用輪差),C15 要紅;--negative gyro-bias-uncomp(注入零偏、關掉零偏估計),C15 或 C3 要紅,寫明是哪一個、為什麼。
  3. 上位影響:C11(Nav2 90 s)、C14(AMCL 重定位)在融合開的預設下重跑,數字與融合前並列。
  4. 假受控體與 Isaac 都跑;Isaac 用 lockstep。

D. #7 的延續:realtime 抖動來源(優先序最低,閒時穿插)

  • GOAL 6 的下一步照做:把韌體讀 CNT 的值與讀的虛擬時刻記進 g_dbg,跟 ContinuousEncoder 算給它的值逐筆對。
  • 對得上 → 問題在受控體取樣 / 錨點時間;
  • 對不上 → 問題在 Renode 的讀取路徑。
  • 同一個閒時視窗量 realtime 的 C13。 陀螺儀預設掛上之後,realtime 在負載下(renode/wall 0.21–0.39)沒有接觸也亮 SLIP。定因紀錄在 issue #7:陀螺儀乘上時鐘比之後,直行段不再誤報;轉向開始那一刻在 0.33× 仍亮,輪差量測本身也在控制週期之間跳(與 C9 同源)。閒時五次要報 C13 誤報數;有誤報的話,不准改門檻或平均窗,先拆是陀螺儀還是輪差那一側。
  • C9 上限不准動。 只在 load < 6 時跑,每個數字附 uptime。

  • 缺口修 Renode、不改韌體語意,韌體照 RM0090 與 datasheet;

  • [HARD] 韌體沒有模擬模式。 融合、零偏估計、加速度計判斷都走真板也會走的路徑;橋接只寫感測器值,不替韌體判斷。
