目標(一句話)

同一台車、同一套橋接與判準,把韌體從「教學級底盤控制器」推到「真車驅動板的形狀」,每一步都在純軟體裡驗到綠,並把路上踩到的 Renode 缺口修掉。

四條線(順序 A → B → C → D;A 是主線,後三條不擋 A 但等 A 的介面定案)

A. 編碼器改走 TIM encoder mode(#2)

Renode 1.16.1 的 STM32_Timer 沒有 encoder mode,預期紅 → 修 Renode(NUnit + 探針原版紅/修正版綠)→ 橋接改驅動正交脈衝或寫 CNT(三種注入法各量每步成本再選)→ 兩版韌體讀 CNT → lockstep 全綠、負對照(兩路對調)紅、realtime 同腳本對 lockstep 的差要能只用節拍統計解釋。35 篇 §5.1 的開放項改寫成結論。

B. 加減速限制、前饋、整定;馬達層加電流限制與摩擦(#3)

先量步階響應再改(假受控體 + Isaac 各一次,寫成基準表)。斜坡與前饋進 calib,兩版韌體同改;受控體三個實作(Rust Fake、Python、Isaac)同一份馬達公式。新增 C9(加速度上限)與負對照;Isaac 滑移與方形閉合誤差目標先量再定,不硬湊。

C. 安全 I/O 五項(#4)

IWDG、驅動器故障腳、bumper、堵轉、心跳。每項:韌體 + 橋接/受控體那一側 + 一個 --negative 旗標;flags 位元進 odom 與 CAN 狀態框。IWDG 先盤點 Renode 的看門狗模型逾時會不會 reset——不會就是缺口,修。新增 C10。

D. Nav2 in the loop(#5)

受控體加假雷射(矩形房間 + 方塊,SCAN 一行),橋接只轉譯;driver 加 /scan 與靜態 TF;Nav2 最小 bringup。NavigateToPose 3 m 級到達 < 0.1 m、不撞方塊;負對照:/scan 全設最大距離 → 撞 → 紅。拉 Nav2 映像(約 +2 GB)前報數字再問。

工作順序

起點驗證 → A-盤點 → A-修 Renode → A-橋接注入法量測 → A-韌體 → A-驗收 → B-步階基準 → B → C(五項各一 commit)→ D。每條線結束:build_site.py + check_docs.py 全綠、對應 issue 回填、commit;push 前問。
