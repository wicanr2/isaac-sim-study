### B. Renode `STM32_Timer` 的 PWM 事件成本(fork 第三個 commit)
現況:10 kHz 載波、三個 `LimitTimer`,自由跑 0.3–0.55×;ARR 拉到 152 Hz 就 1.17×(35 篇 §5.1)。
1. **先量再改**:探針量「每個 timer 事件花多少 µs」,拆成 LimitTimer 回呼、`Connections[n].Set/Unset`、GPIO 傳遞三段;寫進 36 篇 §3 或 37 篇
2. 假設待驗:比較通道各自一個 `LimitTimer` 是多餘的——輸出可以在主計數器的 update event 與讀取時**惰性算**;只有 CCxIE/DMA 才需要事件。改模型,`i @file.cs` 執行期載入,探針:(a) 原本三項修正的 Robot/NUnit 仍綠 (b) `perf_freerun.resc` 在 `pwm_prescaler 0` 下 ≥ 1×(附 load)(c) 閉環 `TIMERFIX=1` lockstep 末端逐字相同、realtime `[warn]` 消失
3. NUnit 加一條(輸出在 update event 邊界的值);fork 分支加 commit,**不合併進前兩個 commit**

### C. vcan ②③ 對照實測(主機已載入 `vcan`)
1. ③ `CreateSocketCANBridge` + 橋接 SocketCAN 後端(Rust std 沒有 `AF_CAN`,零 crate 原則下用 `libc` 層的 raw syscall 或直接 `std::os::unix` `socket(2)` FFI——先查 Rust 標準庫能不能開 `PF_CAN`,不能就寫明用了哪個最小 FFI)
