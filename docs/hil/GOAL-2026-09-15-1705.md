## 三條線(A 是主線,B、C 不擋 A)

### A. Isaac 6.0.1 受控體實測(場域 GPU 主機)
拓撲:Renode + Rust 橋接**留在本機 docker**(維持 GOAL 1 的環境),只有受控體在 GPU 主機。
理由:那台沒有 docker、沒有 root,把 Renode 與 Rust 搬上去代價高;UDP 受控體協定改成可走 TCP,一條 `ssh -L` 就能接。

```
本機 docker:Renode(韌體)↔ Rust 橋接 ──TCP 3700 over ssh -L──▶ GPU 主機:isaac_plant.py(Isaac 6.0.1)
```

要做:
1. 橋接的 `Udp` 受控體加一個 `Tcp` 變體(同一行文字協定,換傳輸),`fake_plant.py` 同步支援 `--tcp`;本機先用 fake 走 TCP 驗到綠。
2. `isaac_plant.py` 上 GPU 主機實跑,逐條回答 38 篇 §6 的七件事;每一條寫「量到什麼」,不寫「應該會」。已知要對的兩點:`physxScene:timeStepsPerSecond` 在 6.0 標 Deprecated([17 篇](../6.0.1/17-physics-parameter-tuning-6.0/README.md) §2),設了要讀回驗;物理後端已查證是 PhysX。
3. C3 容差按接觸滑移實測值重定,寫回橋接的判準與 38 篇 §1。
4. 兩次跑的 CSV 是否逐 byte 相同:`enableGPUDynamics` 讀回;不同就量離散度並定容差,不硬湊。
5. 過了就把 35/37/38 篇與 `isaac_plant.py` 篇首的「未驗證」改成「實測於 …」,數字附條件;沒過的項目留著標記並寫明差在哪。

### B. Renode 三項修正 + 上游 PR
對象:`renode-infrastructure` @ `add012af003a0f620d3da52828262676f374d121`(= 1.16.1)。

| 項 | 現況(1.16.1 實測) | 要改成 | 證據腳本 |
|---|---|---|---|
| `STM32_Timer` 計數週期 | 週期 = ARR(ARR=999 跑 10000 tick → CNT=10;ARR=99 → 1) | 週期 = ARR+1(RM0090:計數 0..ARR) | `examples/hil-stm32/renode/perf_check.resc` 改成專用探針 |
| `STM32_Timer` OC1PE/OC2PE | 未實作,寫入只有 warning | 預載語意:CCR 寫入在下一個 update event 才生效(ARPE 同理) | 新探針:改 CCR 後同一週期內讀 `Connections[n].IsSet` |
| `STM32_UART` TC | 寫清除後永不重設(既有內部專案實測) | 寫 DR 送完後 TC=1;TCIE 時拉中斷 | 新探針:清 TC → 寫 DR → 讀 SR;韌體版:改用等 TC 的傳送路徑看會不會卡 |

順序:**先用 `i @file.cs` 執行期載入驗證修正**(秒級迴圈,不用建 Renode),每項一個負對照(原版必紅、修正版綠);再在 fork 上改原始碼、補 Renode 自己的測試(`tests/` 的 Robot 或 NUnit,照上游既有樣式);最後才自建 Renode 跑上游測試。
**自建成本先講**:Renode 從原始碼建需要 .NET 8 SDK + 約 10 GB、首次 20 分鐘以上、需要網路——這一步只做一次,前面的驗證都用 1.16.1 的 `i @file.cs`。
**送 PR 前先問使用者**;PR 描述用英文,附兩組量測與 RM0090 章節;本 repo 的 36/37 篇引用 PR 連結並標「已送上游 / 已合併」。

### C. 上位接 ROS 2 Jazzy + realtime 模式
1. 一個 rclpy 節點:訂 `/cmd_vel` → 上位框包 → 橋接;橋接的 odom → 發 `/odom`(+ TF)。跑在 `ros:jazzy` docker(需要拉映像,約 1 GB,先報)。
2. 橋接加 `realtime` 模式:不 lockstep,Renode 自由跑、橋接以牆鐘 5 ms 週期取樣與注入;量三個時鐘的分歧(35 篇 §5 的表要補實測數字)。
3. 一段 `ros2 topic pub /cmd_vel` 讓車在假受控體裡走一個方形,`/odom` 回來閉環;判準:與 lockstep 同腳本的末端位姿差在容差內,容差先定。
